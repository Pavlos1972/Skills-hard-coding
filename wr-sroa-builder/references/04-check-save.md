# Check the PDF, then save it

**Check.** `run.py check` reopens the finished PDF and proves, by reading it back: it opens; every heading, figure, narrative and fixed line is on the page in the right order; the ID line sits directly under Owner; the three quote blocks are in order and every CP number is printed; exactly one quote is marked (Accepted); the premium line reads "Premium (incl. R20 policy fee)"; the Record of Advice is Paul's reason and Portfolio Changes is his portfolio reason or "N/A"; FSP45946 and Paul Kafentzis and the typed client name; no "Signed at"; the confirmation, signatures and advisor block sit together on the last page; the two date fields exist and are empty; nothing is clipped; the logo is top left and clear of the title; two signature lines on one level with blank space above.

**You still look at every page image** it makes (the program cannot see these): the logo is the plain one (not the faded circular watermark variant) and does not overlap the title; nothing is crowded; the typed names and captions sit below the signature lines. If something is wrong, tell Paul; never hand-patch the PDF.

**Save.** The PDF goes into the client's own `Servicing` subfolder for this policy, for example `Company - WR Clients\Paul Kafentzis (Client Files)\[Letter] - Files\[Surname, First] (CL)\[Product] - [Policy Number]\Servicing\`. Use the three routes in order (computer, Microsoft 365, Zapier), every try logged. List the folder first and give the file names already there to `run.py name`; it derives the name and stops if the name is taken: then ask Paul, and only with his yes run it again with `--overwrite-yes`. Never touch another broker's folder. After saving, list the folder again and record the folder and the size the listing shows. If no route can carry a PDF, give the file to Paul in the chat, tell him which folder to drop it in and say plainly it was not saved.
