Contents: where the client's folder is, and how to save it on the computer without overwriting.

1. **Connect once, at the start (step 1).** In a cloud chat the computer is a separate machine reached through the device tools. Load them (ToolSearch, `select:mcp__remote-devices__get_device_info,...`), call `get_device_info`, and if `liferisk.co.za` is not in `connectedFolders` call `device_request_folder_access` for `~/liferisk.co.za`: that one request is the only click Paul is ever asked for. Then `device_list_dir` the client's folder and record it with `run.py computer`. If it is refused, `run.py computer --none "<what happened>"` prints the STOP, which is your whole reply.
2. **Find the client's folder** under `liferisk.co.za`, in both locations: `Company - Paul\New Business\{Surname}, {First name}\2. Fact Find\` or `Company - WR Clients\Paul Kafentzis (Client Files)\...\{Surname}, {First name}\2. Fact Find\`. A client's material could sit under either: check both and use whichever has the client.
3. **Never touch another broker's folder.** `Paul Kafentzis (Client Files)` is the only one under `Company - WR Clients` this skill reads from or writes to. If the folder is not found or is ambiguous after both locations were listed, say so in the five-line reply.
4. **Copy (not move)** the file the program built in out/ (its name is derived, never typed): `Teams meeting transcript - DD.MM.YY - (First Surname).docx`. List the folder first; if a file with that name is already there, do not overwrite it: record `save.already_existed yes` and tell Paul. Otherwise copy it to `/mnt/user-data/outputs/` and `device_commit_files` it (no force). Never through Microsoft 365 or Zapier.
5. **Prove the save with the computer's own eyes:** `device_list_dir` the folder (the file's name and size) and run `sha256sum` and `stat -c %s` on the saved file with `device_bash`. The program compares that fingerprint and size with the file it built, and the listed size with the local file's size.
