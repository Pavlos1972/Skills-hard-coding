## Output 1: Planner / AdviceTech note (a copy-ready page, NOT a code block)

**Applies to every meeting - first/Fact Find appointment included.** Paul pastes this into the Planner / AdviceTech task chat, which does not render markdown symbols, so a fenced code block must NEVER be used. `build.py` builds the note as a private page with a **Copy note** button that copies the bold, italics and bullets intact (`planner_note.html`); publish THAT file with the Artifact tool and tell Paul in one sentence what the page is. The page is its only home: after a correction rebuild and republish the same page. Only if the page tool is unavailable, show `planner_note.txt` as formatted chat text, say it is the fallback, and never put it in a code block. Design (approved by Paul; extended to first/Fact Find meetings):

- **Title line:** client name and meeting date in bold, `Name – DD/MM/YYYY`, then on the next line the meeting topic in italics (for a first/Fact Find meeting: `Fact Find (1st Appt / Review Appt): [areas covered]`; for a WhatsApp call: `WhatsApp call, [time]: [topic]`).
- **Pointer line (always, directly under the title):** for a follow-up, `Please view the **Follow-Up Appointment Summary Notes - DD.MM.YY - (Surname, First Name)** file in the client's Fact Find folder.` **For a first/Fact Find meeting, quote the Fact Find Summary PDF instead:** `Please view the **Fact Find Summary - DD.MM.YY - (First Name Surname)** PDF in the client's Fact Find folder.` (`build.py` writes this line itself.)
- **Sections:** bold plain headings with no colons, in the Step 3 order, each of the eight its own heading and only if discussed or still open: `Risk`, `RA`, `Investment`, `RGAR`, `EGAR`, `Medical Aid`, `Will`, `Short-Term`, `Other` (only when notable), then one line naming the areas not discussed, `Applications` (only if something differed - rarely applicable at a first/Fact Find meeting), `Actions`, and last `Next appointment:` in bold. One blank line between sections.
- **Bullets:** real "•" bullets, 1-4 per area, full simple words. First bullet of an area names the quote and its status, or - at a first/Fact Find meeting - the product/insurer being requested and its status.
- **Status words in bold:** **ACCEPTED (verbal)**, **ACCEPTED (verbal + email DD/MM/YYYY)**, **PENDING - client deciding**, **CHANGED:**, **awaiting**, **still open**, **resolved**, **requested**.
- **Actions:** every action is `Sitamah to ...`, each one independent and never worded as conditional on another unless the transcript/Paul said so (per the Accuracy rule above), and each one passing the Step 1b source trace.

A model note, built from invented data, is in `references/planner-note-example.txt`; the structure to reproduce is whatever `build.py` produces.
