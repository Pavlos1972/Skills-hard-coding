## Message to Sitamah (Paul's rule - every Teams meeting and every WhatsApp call, every time)

Rule taken from `fact-find-summary` / `ff-population-transcript` Step 8 so the follow-up skill sends the same message. **It applies to a WhatsApp call too (Paul's rule): the words "Teams Appointment Completed" become "WhatsApp Call Completed"; everything else is the same.** Example: *First Last (Review Client) – 3rd WhatsApp Call Completed: 05/11/2026 – Please see instructions in Client / Prospect Task.*

**When it is SHOWN and when it is SENT (Paul's rule).** It is SHOWN in the same reply as the Planner page and the PDF (follow-up only), once they and the hand-offs are produced, checked and SAVED (saved files confirmed by listing the folder back): one reply, one question ("Shall I post this message to Sitamah in Teams?"), so Paul approves all three together. Never end a reply without the message in it. It is SENT only after his yes. If any output is still being corrected, do not send.

**The message** (one message to Sitamah in Teams, BOLD and in a much larger font than normal chat). `build.py` writes it to `out/teams_message.txt`; use it exactly as built:

`[Name Surname] ([Review Client] or [Prospect]) – [1st / 2nd / 3rd ...] Teams Appointment Completed: [DD/MM/YYYY] – Please see instructions in Client / Prospect Task. [Please take note of Follow Up Appt.]` (the dashes are en dashes)

- Example (Prospect, first meeting, follow-up booked): *First Last (Prospect) – 1st Teams Appointment Completed: 05/12/2026 – Please see instructions in Client / Prospect Task. Please take note of Follow Up Appt.*
- Example (Review Client, no follow-up booked): *First Last (Review Client) – 2nd Teams Appointment Completed: 13/10/2026 – Please see instructions in Client / Prospect Task.*
- **The label after the name (Paul: it depends on whether the person is a Prospect or a Review client):** `(Review Client)` for an existing client, `(Prospect)` for a prospect. Decide it from where the client's folder sits: a client in `Company - WR Clients\Paul Kafentzis (Client Files)` is a Review Client; a client in `Company - Paul\New Business` is a Prospect. If it is unclear, ask Paul - never guess. Recorded in `client_status` and `client_status_basis`; the program checks the label against the folders you read.
- **The number (1st / 2nd / 3rd ...)** applies to both Prospects and Review Clients: count the Teams meetings with this client on file (Fact Find meeting, every Follow-Up Appointment Summary Notes file, plus this one). For a WhatsApp call count every meeting and call on file (Fact Find, every Follow-Up Appointment Summary Notes file, every WhatsApp Call Summary), plus this one. A first Fact Find meeting is normally `1st`, but a Review Client with earlier meetings on file is counted from those. If it genuinely cannot be worked out, ask Paul - never guess. Recorded in `appointment_number` and `appointment_number_basis`.
- **Follow-up sentence - CHECK BEFORE DRAFTING:** open the finished PDF/Summary and the Planner note's `Next appointment` line and decide from THOSE. `Please take note of Follow Up Appt.` is included ONLY when they show an actual follow-up appointment that was agreed or booked (a specific date/time, or Paul and the client clearly fixing the meeting). A vague intention ("we'll chat again in February", "date to be set", "revisit later") is NOT a follow-up appointment: leave the sentence out. When the two disagree, or it is unclear, ask Paul - never assume. This is recorded in `next_appointment.agreed` and `next_appointment.check`.
- **Show your check:** in the reply that presents the message, say in one line what the Summary and Planner note say about the next appointment and therefore why the follow-up sentence is in or out.
- The date is the meeting date, always DD/MM/YYYY.

**The route is hard-coded: Zapier only.** The driver prints the exact steps for this client's message. The Microsoft 365 connector cannot send Teams messages (no ChatMessage.Send permission: 403 confirmed). Post only into the 1:1 chat labelled "(1:1 Chat) Paul Kafentzis, Sitamah Nathoo", never into a client meeting chat or any other chat. If the Zapier call fails, say so plainly and give Paul the message text to paste himself; never claim it was sent.

**Once per meeting:** `ff-population-transcript` and `fact-find-summary` send this same message for a first/Fact Find meeting. If it was already sent for this meeting in this chat, record `teams.status=already_sent` with `teams.already_sent_evidence` and do NOT send again.

**The program holds the message back:** it is shown only when every other check has passed, so the message can never go out and the run then fail. Record `teams.body_as_stored` (what Zapier says it stored); the checker compares it with the message.

**Check and report:** Zapier returns a message id and sent time; report both in one line ("Sent to Sitamah in Teams at HH:MM, message id ..."). Treat the send as unconfirmed until that result is seen. Record it with `run.py receipt`: `teams.status=sent`, `teams.message_id`, `teams.sent_time`, `teams.approved_by_paul` (his own words of yes). If Paul says no: `teams.status=declined`, `teams.paul_said`. If it fails: `teams.status=failed`, `teams.detail`, `teams.text_given_to_paul=true`.

**Permission:** sending a message for Paul needs his clear yes each time. Show him the exact message in the reply that presents the deliverables and send it only after his yes to the one question. Never send earlier, never twice for the same meeting (a correction does NOT trigger a resend unless Paul asks), and never for a client whose documents are not all saved.
