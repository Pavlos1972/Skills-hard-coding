# Step 8: Save

**Every completed report MUST be saved in the client's `Analysis & Comparison Reports` folder. No exceptions.** Never leave a report in the source-document subfolder (`6. Policy Schedules` root), loose in the client's folder root or anywhere else; the slide PDFs go in the same folder.

1. **Find the folder** (computer first, then Microsoft 365, then Zapier, every try logged). Look where it actually sits: for one client it is inside `6. Policy Schedules`, but folder numbering differs between clients, so check the client's subfolders rather than assuming the path.
2. **If the folder does not exist,** create it in the same place the client's other report folders or policy schedules sit (normally inside `6. Policy Schedules`), save the files in it, and tell Paul in the reply that it had to be created. Never save somewhere else instead.
3. **File names are derived by the program:** `First_Surname_Insurer_Policy_Analysis - DD.MM.YY.pdf` (the product is added before `_Policy_Analysis` when one insurer has more than one policy for the client); Report 1 `First_Surname_Insurer_Policy_Analysis_Slide - DD.MM.YY.pdf`; Report 2 `First_Surname_ProposedAbbrev_VS_CurrentInsurer_Policy_Analysis_Slide - DD.MM.YY.pdf`.
4. **One PDF per policy for the detailed analysis,** never merged. The client slides are the one place where same-insurer policies are combined (one deck per insurer).
5. **Save straight into the final folder,** not first into another folder to be moved later. **Never overwrite an existing file without Paul's yes:** if the program finds a file with the same name it stops; ask Paul.
6. **Verify after saving:** list the folder and record the listing (`save.folder`, `save.listed "name=bytes;..."`); every size must equal the local file.
7. Present each PDF to Paul in the chat too: the reply is never a substitute for the saved PDF, and the chat copy never replaces the saved copy.
