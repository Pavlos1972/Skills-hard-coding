# Mapping the sources to fields: the rules

## Map the sources to fields — rules

- **Only fill in what is in a source** — the Audio to Text file, the transcript, the Overview or a client document.
- **How the sources combine (rule 11):**
  - The Audio to Text file is the base. Every populated value goes in, whatever its status.
  - The transcript fills every gap the Audio to Text file leaves (unclear, blank or `empty` fields), and adds the context (reasons, who pays what, timing, plans) to the relevant field or Notes.
  - Where both give the same answer, state it once, as fact.
  - Where they differ, the Audio to Text value is written and the difference flagged, quoting both values and where each came from, so Paul can decide. A difference only in spelling, format or level of detail is not a conflict - use the fuller/cleaner value and do not flag.
  - The Overview is cross-checked against both; differences are flagged, never silently resolved.
- **Never guess or invent a value.** Mark unanswered fields "N/A", "Not discussed", or "Requested" as appropriate.
- **"Not discussed" is a claim, not a default — verify it before writing it, against the Audio to Text file, the transcript and the Overview.** Re-search all three, and the client's other documents, before marking anything "Not discussed". **Named precedent:** [client D], 1 September 2026 — four debt fields were wrongly marked "Not discussed" when all four were answered on the call. **Named precedent:** [client B], 09.10.26 and [client C], 12.10.26 — drafts built from the transcript alone left fields open that Paul's own Fact Find record had already answered.
- **When a field can't be resolved from the Audio to Text file, the transcript or the Overview, check the client's other documents on file before marking it unconfirmed.** A policy schedule, servicing record, application, payslip, benefit statement or welcome pack can confirm a beneficiary nomination, a policy number, a tax number, contact details, or similar. **Named precedent:** [client A], 07.10.26 (review) — checking the BrightRock Owner's Manual already in the client's folder answered a beneficiary question Paul couldn't answer live: Estate [x]% / [beneficiary] [y]% (flagged only as pre-dating the client's March 2025 marriage).
- **The policy schedule (or the insurer's own equivalent current-policy document) is the ultimate source of truth for a policy number — never an Overview spreadsheet, a prior Fact Find, an Audio to Text entry or a quote/FNA reference number.** Resolve conflicts against the most recent genuine policy document and state the resolved number as fact, mentioning in one line that it differs from the Audio to Text file/Overview. Do not confuse a policy number with a quote/FNA reference number. **When the conflicting document is itself one Claude can correct** (e.g. the WR Overview spreadsheet), correct it directly (the save rule is on page 07). **Named precedent:** [client A], 07.10.26 (review) — the WR Overview spreadsheet recorded [policy no. B]; the Owner's Manual and Change Moment Pay-out Guide (both dated 11.07.24) agreed on [policy no. A]. Corrected in the Fact Find and in the spreadsheet itself.
- **For any other value where a source document disagrees with the Audio to Text file** (for example a benefit statement showing a different fund value), the Audio to Text value is written under rule 11 and the document's figure is flagged prominently with both values, so Paul decides. Never silently use the document's figure and never leave the difference unflagged.

- **An FNA, Shortfall, or Reduced quote request must state two things explicitly, everywhere it is written: (1) WHICH INSURER the quote is to be requested from, and (2) whether it is Servicing or New Business — never left as just "a new FNA/quote".** **Servicing** — the insurer makes the quoting changes inside the client's existing policy; **New Business** — a fresh quote that would create a *second, separate* policy. **There is no default (Paul: "no servicing whatsoever"). Never assume Servicing because the client already holds a policy with that insurer, and never assume the insurer.** Take both from the Audio to Text file's quote fields (type of quote and insurer) and from what Paul said on the recording. **If neither source says which insurer to request the FNA / Shortfall / Reduced quote(s) from (or whether it is New Business or Servicing), ASK Paul before the Fact Find is finalised** (AskUserQuestion, or a plain-text question if unattended: "Which insurer should the FNA, Shortfall or Reduced quote(s) be requested from, and is it New Business or Servicing?"). If the recording is unclear on the insurer even though the Audio to Text file states it, use the Audio to Text value and flag the unclear recording. Applies equally to an FNA, a Shortfall quote (Group Risk), and a Reduced quote. **Named precedents:** [client A], 07.10.26 (review) — Paul specified a BrightRock Servicing FNA against the existing policy ([policy no. A]), not a New Business quote. [clients F and G], 14.10.26 (spouses, one meeting) — the first draft defaulted to Servicing because both held policies with the same insurer; Paul set a BrightRock New Business FNA plus Reduced Quote 1 and 2 for each spouse, and said Servicing must never be the default.
- **When an FNA/Shortfall/Reduced quote is being requested alongside a separate client-side document request (e.g. an updated medical/psychiatric report), do not make one conditional on the other unless the transcript or Paul says they genuinely are.** Request the quote from the insurer and request the document from the client as two independent actions in parallel — never word one as "pending"/"once received" the other unless that dependency was actually stated. **Named precedent:** [client A], 07.10.26 (review) — a first draft wrote the BrightRock Servicing FNA as "pending the updated psychiatric report", implying Sitamah should wait for the report before requesting the FNA. Paul corrected this: Sitamah emails the client for the report AND independently requests the FNA from Lizelle Cachado at BrightRock with the FF's changes and all the same loadings — the two run in parallel, neither blocks the other.
- **Debt details are captured in full, every debt.** Lender/bank by name, type, term remaining, monthly repayment, outstanding balance, asset value, owner/payer, credit-life status. Only mark `Requested` if genuinely missing after checking the Audio to Text file, the transcript, the Overview, other documents, and Outlook.
- **Totals must reconcile to the cent — and debt is never excluded from a calculation by judgment call.** Whether a debt carries its own credit life cover is recorded as fact only — never a reason to exclude it from the Risk Calculation's debt deduction; that is Paul's call to make, not Claude's. Where the Audio to Text file carries its own totals (gross, net, take-home, budget, debts, childcare, risk-calculation figures), recompute them from their components and reconcile; flag any difference. **Named precedent:** [client D], 1 September 2026.
- **Flag, don't silently resolve, genuine ambiguity — but a flag is a claim too, and needs the same bar of evidence as any other field.** Don't manufacture ambiguity that isn't there — a specific, plausible value should only be flagged when a source itself contains a genuine contradiction or nonsense reading.
- **Every "see flag" or "see notes" cross-reference must point to a flag or note that actually exists in the section it names.** **Named precedent:** [client E], 14 September 2026.
- **Derive fields the layout implies but nobody stated outright.** E.g. Date of Birth and gender from a South African ID number (first 6 digits YYMMDD; the next four digits below 5000 mean female) - and cross-check against the Audio to Text file. If a 'number of years' field holds a year (for example 2015) instead of a count, work out the years (the meeting year minus that year) and show it as "since 2015".
- **Route anything important that doesn't fit a field into that section's Notes.**
- **Pending items stay pending**, stated explicitly (e.g. "Pending — RGAR to be prepared for next meeting").
- **Dread Disease Cover Target defaults to R500,000 lump sum unless otherwise indicated.** Per Paul's standing instruction (15 September 2026). Companion rule to `fact-find-summary`'s Section 8. If the Audio to Text file shows a different dread disease figure, treat it as a deliberate entry and note the deviation and its source.
- **Standing ABI values in the Risk Calculation — fill in automatically, every client, without asking:**
  - **Life cover: fractured cover:** `Life Cover (WOL) ABI` = **3%** and `Childcare ABI` = **5%**.
  - **Permanent disability: fractured cover:** there is **no** `Life Cover (WOL) ABI` line (there is no such thing as a Life Cover (WOL) ABI under Disability — never show it). In its place the line is `Household needs ABI` = **5%**. `Childcare ABI` = **5%** stays. If the Audio to Text layout has no Household needs ABI line, add it as the standing rule requires and say so in one line.
  - **Dread Disease ABI Value = 3% always, unless Paul states otherwise for that client (the new form presets 3%).**
  - A different ABI sitting in the Audio to Text file for one of these is used only if Paul stated it for that client; otherwise the value above is written and the difference mentioned in one line in the section notes (this is one of the two named exceptions to rule 11). Only a different ABI that Paul states explicitly for that client overrides it, and then the deviation and its source are noted.
  - This does **not** set the ABI for Standard Life Cover, Standard Permanent Disability or Income Protection, and does **not** set any ACI (annual contribution increase) field - those are filled from what the Audio to Text file contains or what was said, otherwise `Pending – FNA`; if in doubt, ask Paul. A "?" left in an ACI value field is not a value: show `Pending – FNA`. Companion rule to `fact-find-summary`'s Section 8: both documents must show the same ABIs.
- **Business Assurance:** only populate if Business Owner = Yes.
- **Meeting logistics** go in a final "Next Steps & Next Meeting" section, separated from the numbered sections.
