# The Outlook draft (Claude in Chrome; never sent by Claude)

After saving, put the proposal into an Outlook **draft**. Claude never sends it.

- **To:** the client's email address. **Cc:** Sitamah Nathoo (admin@liferisk.co.za), always. **Subject:** exactly the one the program printed (character for character, the en dash included).
- **Method (the most reliable):** (1) create the draft shell with the Outlook connector's `outlook_create_draft` (to, cc, subject, a simple placeholder body): this guarantees the recipients and the subject; (2) open the draft in Outlook on the web with Claude in Chrome (a new tab; go to `outlook.office365.com/mail/` first, wait, then the draft's webLink; click the edit pencil); (3) replace the body with the contents of `draft_body.html` by dispatching a **paste event** that carries the HTML (`ClipboardEvent('paste')` with a `DataTransfer` holding `text/html`) on the `[aria-label="Message body"]` element: plain `innerHTML` assignment loses bold and table borders; (4) add Paul's signature: see the signature setting below; (5) Options > **High importance**; (6) let it autosave (wait about 8 seconds) and confirm.
- **Signature.** `assets/settings.json` says how the signature gets into the draft. `insert` (the setting today, this skill's way): Insert > Signature > **"Paul K New"**, which already holds "Kind regards,", the logo and the disclaimer, so the pasted body has no second "Kind regards," and no template signature block. `server`: the Exchange rule of `paul-email-signature` adds the signature at send time and Claude inserts nothing. **Which is right is an open question with Paul** (does the client's email show the signature once or twice?): until he answers, keep `insert` and let the audit say so. The program's read-back check follows the setting (exactly one "Kind regards," for `insert`, none for `server`).
- **If DOM edits made after the paste do not persist,** make the change through the editor (for example `execCommand`) so Outlook registers it, then check again.
- **Do not type into Outlook's compose fields by coordinates:** the compose pane re-lays-out as it loads and text lands in the wrong field; use element refs, and only ever ONE compose window. Do not press Ctrl+S in the compose window (it can insert a stray Loop component); if a Loop box appears, remove it before finishing.
- **Read it back:** `read_resource` on `mail:///messages/{id}` (the result is large: save it to a file and parse the file, never paste it). Give that file to `run.py draft`. The program checks To = the client, Cc = Sitamah, the exact subject, importance High, tables open = close, "Kind regards," as the setting says, no placeholder, no Loop component, bold headings, and that every fund, fee, date and the contribution are there.
- **Clean up:** close the Chrome tab; delete any stray blank drafts Claude itself created while doing this (`outlook_delete_draft`) and say so; record `draft.tab_closed yes` and `draft.stray_deleted <number or none>`.
- Attachments are NOT added by Claude: Sitamah reviews the draft, attaches them and then sends the email.
