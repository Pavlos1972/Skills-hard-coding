# What the build does (nothing here is typed by you)

`run.py build` fills `assets/OM_TaxFree_Proposal_TEMPLATE.html` from your confirmed answers and makes three files. You never edit the template, a script, the data or the HTML. If something is wrong, fix the answers and rebuild.

- **The full email (with the logo)**, named `[FirstName]_[Surname]_OM_TaxFree_Proposal_Email - [DD.MM.YY].html` (the build date; derived, never typed). Send it to Paul in the chat. Then continue: the build is not finished until the save, the draft and the message are done.
- **The saved copy (no logo)**: the same file with the logo paragraph removed. **The copy saved in the client's folder is ALWAYS the no-logo copy**: the signature logo is a long base64 string that cannot be uploaded reliably, so never risk a corrupt image and never truncate or retype it by hand. Tell Paul plainly that the saved copy has no logo (the Outlook draft gets Paul's signature and logo separately).
- **The text for the Outlook draft** (`draft_body.html`): everything from "Dear {Client}," to the next-meeting line: no header block, no template signature, no "Kind regards,", `<b>` not `font-weight`, a blank line between paragraphs (Paul's Outlook shows no gap with bare paragraph tags), borders on the table cells.

**Fixed by the template and the program**
- The header: From Paul Kafentzis; **Sent** = the build date and time (South African time); **To** = the client's email; **Cc is ALWAYS "Sitamah Nathoo"** (never blank, never removed); **Subject** = `{Client full name} / Old Mutual Tax Free Investment Proposal – R {contribution} p.m.` (the en dash included; the same subject, character for character, goes on the Outlook draft); Importance High.
- Money: `R` and a space, thousands commas, no decimals unless the source shows decimals. Percentages keep the quote's own decimals, never rounded.
- The fund allocation table has one row per fund in the quote's table, then "Total allocation 100%". The Total Ongoing Fees table is assembled from the four fees, with the total added up by the program, not copied from the quote's own layout.
- **The Personal Investment Target paragraph is fixed text, not per client:** "inflation plus 4-5% after asset management fees" and a recommended minimum investment period of "5-7 years": never derived from the quote and never asked.
- The "Attachments" list is the fixed three lines (Tax-Free Investment Quote / Fund Fact Sheets / Wealth Investment Strategy Summary); change it only if Paul tells you the attachment set differs for this client.
- **The fund allocation table and the Total Ongoing Fees table use a fixed `width="624"`, not `width="100%"`, on purpose:** a percentage width loses its 680px-wrapper constraint when pasted into Outlook and stretches edge to edge. Never change it back.
- The tax facts in the product paragraph (annual limit, lifetime limit, the rate on contributions above the limit) are in ONE place, `assets/tax_facts.json`. They are kept exactly as in Paul's template and are not verified by the skill; change them there, and only there, when the tax year changes.
- The next meeting reads "Teams Meeting on {weekday, DD/MM/YYYY} @ {time}" and the meetings already held "{weekday, date} & {weekday, date}": the weekdays are computed by `scripts/tax_free_dates.py`, never by hand or from memory.

**Saving.** The saved (no-logo) copy goes into the client's transaction folder under **Comparative Quotes**: never only shown in the chat. Location: the `Paul` SharePoint site > `New Business` > `{Surname}, {FirstName}` > `{Plan owner} - (OM Tax-Free - R{amount})` > `Comparative Quotes`, the same folder the sources were read from (it syncs to Paul's computer, the "One" drive). **If the path does not exist, create the folders under the client's existing Client Files folder (`WR Clients > Paul Kafentzis (Client Files) > {Initial} - Files > {Surname}, {FirstName}`) and tell Paul.** How: if a local folder from Paul's computer is connected to the session, write the file there; otherwise find the folder with `sharepoint_folder_search` (parameter `name`) and upload with `sharepoint_upload_file` (driveId + parentItemId of that folder, `expectedBytes` = the file size, `conflictBehavior: "replace"` only when re-saving a revision with Paul's yes). Confirm by reading the folder listing. If the HTML is revised (for example a Cc or wording fix), re-save over the same file name and tell Paul. Tell Paul the folder and file name in plain words when done.
