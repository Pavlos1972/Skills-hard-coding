Contents: where the client's documents are, the routes, the roles to register, and the failure to recognise.

- **Where:** the client's own folder, `liferisk.co.za\Company - Paul\New Business\[Surname, First Name]\...` (also check `Company - WR Clients` -> `Paul Kafentzis (Client Files)`). A client can have several sibling folders for different products at once: confirm which one matches the bundle being built before pulling documents from it; never assume the first result is the right one. Client documents almost never arrive as chat uploads.
- **Routes, in order, every try logged:** 1 the computer (device bridge), 2 the Microsoft 365 connector (`sharepoint_search`, then `read_resource` on the hit's uri: a search result is only a snippet), 3 Zapier. Ask Paul to upload something only after all three were tried and failed. If a targeted search with a folder name finds nothing, retry with a broader folder name or without the filter before concluding the document does not exist.
- **Subfolders to expect:** `1. Overview` (the latest "WR Overview" PDF), `2. Fact Find`, `Comparative Quotes`, `Applications`, `ROA & Bus ROA`.
- **Roles to register (`run.py doc --role ...`):**
  - Risk (required): `fna_quote` (the FNA quote), `application` (the insurer application), `follow_up_notes` (the latest Follow-Up Appointment Summary Notes), `fact_find_summary` (the Fact Find Summary, for the client's name and ID). Optional: `accepted_quote` (the latest Reduced, Revised or accepted quote; if the client accepted the FNA in full, the FNA quote serves as both: `--same-as fna_quote`), `overview`, `risk_tolerance`.
  - Retirement and Investment (required): `proposal_email` (what was sent to the client), `client_reply_email` (the client's own reply confirming the go-ahead: a different document, and the ROA needs both), `fact_find_summary`. Optional: `risk_tolerance`. There is no FNA quote or accepted quote for these bundles.
- **Verify every required document is present and current** before going on: do not build from whatever is in the folder. Flag gaps (only a raw intake form on file, a proposal for a different amount than the one advised on) and ask Paul rather than silently substituting the nearest document.
- **Outlook:** if the accepted proposal is not saved as a PDF, find it in Outlook (`outlook_email_search` / `read_resource`, match on the subject thread: beware sibling threads for other transactions with near-identical reply text) and save it as a PDF or HTML page.
- **Recognise this failure at once:** a Fact Find or KYC PDF read through SharePoint often comes back as field labels with none of the client's answers (the filled-in layer is not extracted). Multiple pages of labels with no values is the tell. Do not conclude the document is blank and do not ask Paul to retype values. Read the PDF from the computer, or ask Paul to attach that PDF.
- The quote-reading method is validated for **BrightRock** proposals only. If the quote is from another insurer, tell Paul before going on; the program does not accept it silently.
